博客配图，哪些交给 AI，哪些留给自己选

2026 · 11 · 07 · 3 min · Agent / Python / 开源

最近在想博客配图时，我碰到了两种很不一样的需求。有时文章已经写完，只想尽快找到一张合适的封面。有时想发的就是手里那张图，比如和 AI 讨论方案时的一段界面截图。前一种需要帮忙找，后一种需要保留自己挑选的细节。

让自动找图有明确的交付

如果点「AI 配图」，我希望看到几张候选，以及每张图适合放在哪一段。候选项应带原始链接和使用条件，方便检查能否用于公开博客。找到合适的图后，裁剪尺寸、压缩、命名和补充替代文本都可以一起处理。没有合适的候选时，文章依然可以先按纯文字排版。

想分享的是对话中的某个转折

如果自己提供截图，我更在意哪几句话会被读者看到。拿 Auto Blog Agent 举例，可以挑出讨论文章语言的几轮，把从「按地区猜语言」转到「看已有正文和作者设置」的思路讲清楚。原界面有现场感，遇到长截图时，也可以把选中的消息整理成更易读的对话摘录，保留说话人，标明省略的地方。

AI 可以标记可能需要遮挡的信息，给出裁剪建议，并把处理后的图片插到文章里。我想在预览时亲自看一遍最终画面，因为是否公开一句话、一个头像或一段项目细节，取决于自己愿意分享多少。

两个入口，共用一次预览

同一篇文章可以用自动找到的图做封面，在正文放自己挑的截图。草稿预览应该展示读者最终看到的图片和说明。这样，我可以一次确认文章和图片的公开范围，把重复的处理工作交给程序。

这还是配图功能的设计。先从本地图和对话截图入手，可以尽早验证选图、遮挡、预览这一段是否顺手。之后再接自动找图，沿用同一套插入和预览方式。
