让 AI 帮忙记录时，怎样保留真实的自己

2026 · 11 · 04 · 4 min · Agent / Python / 开源

整理博客时，我发现一些条目连自己都不记得写过。检查页面后，能确认其中一部分只是链接到 # 的占位内容，并没有实际文章。但它们带着标题、日期和简介，放在列表里，很容易被理解成已经完成的记录。

这也提醒了我：一个页面看起来完整，与它是否准确反映真实经历，是两件需要分别检查的事。对于正在做的博客 Agent，这个问题尤其具体。

身份背景不能代替真实经历

我是一名关注 AI、编程和独立开发的大学生。这些信息可以帮助系统判断主题是否合适、表达深度是否自然，却不能证明我实际使用过某个工具、完成过某次部署，或者拥有某种成果。

所以，公开资料适合整理成工具介绍和技术说明；个人记录则需要对应真实素材。系统知道我接触过 Python，不意味着它可以替我写“在多个生产项目中验证过”。

表达可以认真，进度必须准确

我希望项目介绍有质量，也能讲清楚设计上的考虑。架构拆分、审核规则和预算控制，本身就值得说明，不需要额外添加用户规模、性能数据或成功案例。

目前 Auto Blog Agent 跑通了本地测试和离线流程，真实模型与自动发布还需要联调。把两部分放在一起写清楚，读者才知道哪些可以尝试，哪些仍然只是目标。

Create 与 Observe 应该承载不同内容

Create 用来展示做出来的东西：项目解决什么问题、采用什么结构、目前能运行到哪一步，以及源码在哪里。Observe 用来记录围绕这些工作的观察和思考：遇到了什么问题，哪些边界值得重新考虑。

同一个项目可以在两边出现，但不必重复介绍。项目页提供可核对的实现信息，思考文章保留上下文与问题。这样读者能看到作品，也能理解作品背后的取舍。

允许博客留白

希望减少每天写作的负担，是这个项目的出发点。持续更新仍然需要真实素材和足够资料；没有合适内容时，可以跳过，也可以只保留草稿。

今天的整理先从移除没有详情页的占位条目开始。对于已有实际页面的旧内容，仅凭“记不清”还不足以判断真假，需要再核对原始素材。博客可以慢一点更新，但每一条公开记录都应当有依据。
