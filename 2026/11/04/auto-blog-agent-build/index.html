Auto Blog Agent：把博客自动化拆成可执行的模块

2026 · 11 · 04 · 4 min · Agent / Python / 开源

最近在推进的 Auto Blog Agent，来自一个实际需求：希望持续更新技术博客，又不想每天重复选题、整理资料和处理发布。项目已经开源，本篇记录目前具体做出了什么，以及接下来需要打通的部分。

项目入口：Skill 与程序各司其职

仓库保留 SKILL.md，描述身份约束、素材使用方式和执行步骤；实际工作由 Python CLI 承担。支持 Agent Skills 的工具可以读取规则并调用程序，GitHub Actions 则提供独立的调度入口。

这种拆分让写作规则与执行逻辑可以分别维护。修改身份和编辑偏好时，不必重写程序；执行预算、输出文件和发布检查，也不只依赖模型是否记住提示词。

目前已有的处理链路

程序从配置的 RSS 来源读取选题，按关键词筛选，与 SQLite 中的历史记录比较，再将来源摘录、身份和编辑规则交给写作模型。正文生成之后，由另一次模型请求独立审核，同时执行程序规则检查。

输出包括 Markdown 正文与 JSON 审核报告。可能涉及个人叙述、代码执行验证、来源不足或重复内容时，文章会留在草稿路径。模型 API 使用环境变量配置，预算在请求前预留，超过每日上限停止调用。

已经验证的范围

目前本地五项测试和 Skill 格式校验通过，离线 Dry Run 能输出文章和审核报告。仓库也包含 GitHub Actions 工作流与向 GitHub 仓库新增 Markdown 文件的接口。

这些结果对应的是基础执行链路。真实模型生成质量、事实核验效果，以及长期无人值守运行还没有完成联调，自动发布仍保持关闭。

博客接入暴露出的适配问题

这个博客使用 HTML 页面，文章还需要进入 Create、Observe 与 Archives 列表。通用 Markdown 输出不能直接完成这些操作。目前博客更新通过单独的脚本按模板生成页面，再把正文与列表改动放进同一次提交；这部分还没有整合成 Skill 的通用适配器。

下一步优先解决持久状态、发布恢复和 HTML 博客适配，然后再考虑封面与更多平台。这样每增加一项能力，都能对应到具体可检查的行为。

11 月 5 日更新 · 给无人值守任务加一份故障报告

定时任务失败后，我最想知道的是卡在哪一步、内容有没有发出去，以及下一步该检查什么。Auto Blog Agent 现在有一个独立的监测工作流。它在发布任务结束后读取运行结果，在失败时按规则诊断，并在 GitHub Actions 留下 Markdown 报告。

比如，日志里出现 GitHub 拒绝写入的特征时，报告会建议检查目标仓库、令牌权限和分支规则。只凭失败结果无法确定文章是否已经发出，因此重跑前要先核对目标站点。邮件推送可按需开启。

这一版从博客发布出发，也欢迎用在视频发布和其他定时工作流上。项目以 MIT 许可面向全国开放试用，欢迎通过 GitHub Issues 提交案例和合作建议。也欢迎发邮件到 QQ 邮箱或 Gmail。
