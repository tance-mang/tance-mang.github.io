读懂 Python 版本状态：从 3.10 结束支持说起

2026 · 11 · 08 · 3 min · Python / 版本 / 官方文档

选择 Python 版本时，最需要先确认的不是「最新」，而是这个版本还处在哪个维护阶段。官方在 Status of Python versions 页面给出了统一口径：当前 main 面向未来的 3.16，并注明各分支的首发日期、结束支持日期与发布经理。

3.10 已经进入 end-of-life

同一份表格把 3.10 标为 end-of-life：首发于 2021-10-04，结束支持日期为 2026-10-01。按页面说明，进入 end-of-life 后，发布周期冻结，不再接受进一步改动。这意味着继续依赖 3.10 运行环境时，不能再指望官方安全修复窗口。

现在还在支持的分支怎么读

截至该页面当前内容，仍在支持的分支包括：

  • 3.15：bugfix，首发 2026-10-09，计划结束支持约 2031-10
  • 3.14：bugfix，首发 2025-10-07，计划结束支持约 2030-10
  • 3.13：security，首发 2024-10-07，计划结束支持约 2029-10
  • 3.12：security，首发 2023-10-02，计划结束支持约 2028-10
  • 3.11：security，首发 2022-10-24，计划结束支持约 2027-10

页面还说明：表格中斜体日期属于计划时间，发布经理可以按需要调整。核对版本时应以该页面与对应 PEP 为准，而不是二手摘要。

五个阶段分别意味着什么

开发者指南按 PEP 602 描述了五个阶段。粗略理解可以记这几点：

  • feature：可接受新特性；当前 main（未来 3.16）处于这一阶段
  • prerelease：首个 beta 之后，不再塞新特性，但仍可修特性与缺陷
  • bugfix：正式发布后接受缺陷与安全修复，大约每两个月有二进制发布
  • security：通常两年后只接受安全修复，且不再发布二进制包
  • end-of-life：约五年后支持结束，仓库不再继续变更

写自动化或部署脚本时怎么用这份表

如果项目声明「支持的 Python 版本」，最好直接对齐官方状态：把仍在 bugfix / security 的版本写进矩阵，把已经 end-of-life 的版本从默认支持里拿掉，并在文档里链回官方版本页。这样读者可以自己核对日期，而不是依赖文章里的转述。CPython 的发布说明也会出现在 cpython releases；阅读时仍应以版本状态页的阶段定义为准。

本文只整理官方公开表格与阶段定义，不涉及个人升级经历、性能测试或具体业务迁移结果。
