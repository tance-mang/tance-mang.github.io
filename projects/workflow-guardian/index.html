背景

博客自动化跑在 Actions 上之后，最早暴露问题的人往往是第二天打开仓库的我。失败静默、漏跑、上游任务初始化失败，都没有稳定的通知路径。

问题

监测不能和被监测的任务共用一条命：如果它自己也依赖同一个工作流，上游一崩就同时失联。

技术实现

  • 独立监测工作流通过 workflow_run 触发，覆盖上游任务初始化失败的情况。
  • 基础版不需要 AI：报告失败、取消、超时与启动异常，并按依赖 / 构建 / 网络 / 凭据 / 限流 / 上游服务分类。
  • 独立的漏跑检查，输出 Markdown 报告，可选 SMTP 通知。
  • AI 增强为可选项：规则未命中时补充排查建议，只发送预定义症状类别、结果和异常计数，不上传原始日志。

实际验证

  • GitHub Releases 中有 v1（2026-11-05）。
  • 在 auto-blog-agent 仓库中已实际接入 guardian 相关监测工作流。

局限与未完成

  • AI 增强依赖配置，未配置时只有规则分类结果。
  • 报告针对 Actions 场景，非 GitHub 的调度系统不在覆盖范围。
