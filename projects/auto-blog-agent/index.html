背景

博客更新长期依赖手动整理：想法散在对话和代码记录里，发布时再重新抄一遍。我想把选题、写作、审核、发布变成一个可以被检查的流程，而不是每次都靠记性。

问题

自动写作最容易出的问题不是写不出来，而是四件事：身份漂移（AI 写成通用口吻）、重复发布、token 成本失控，以及失败之后没有人知道发生了什么。

技术实现

  • 身份与编辑规则写在 memory/PROFILE.md 与 EDITORIAL.md，私人素材放在不提交的 private/INBOX.md。
  • 选题来自 RSS，来源摘录受 allowed_hosts 白名单约束。
  • 写作与审核是两次独立请求，审核结论落进 review.json，不由同一次输出自我认证。
  • 历史去重 + 保守预算预留：失败请求同样占用额度，按配置时区在次日重置。
  • 语言不靠 IP 或时区猜测，由正文样本判定并记录判断依据；证据不足时要求显式配置。
  • 发布默认关闭，先 Dry Run；正式发布用 GitHub Contents / Git API 在一次提交里同时写入文章与两处导航列表。
  • 失败由独立监测工作流接管，生成故障报告而不是静默重试。

实际验证

  • 仓库测试在 Actions 的 test.yml 中持续运行：python -m unittest discover -s tests -v。
  • 离线样例 generated/demo 不调用模型、不写真实历史、永不发布，每次重复运行均可重现。
  • Auto blog 工作流按计划（每小时）持续执行，2026-11-15 的运行记录状态为 success。

局限与未完成

  • README 明确标注：真实模型与真实博客联调尚未完成。
  • 截至 2026-11-15，本站仓库中还没有由该流程自动产生的发布提交。
  • 兼容 Chat Completions 的服务需要各自实测，不保证开箱可用。
  • 在线博客历史自动导入、多语言审核全面验证、Draft PR 与可靠恢复仍未完成。
